CI/CD Pipeline Testing Guide

Step-by-step instructions for running tests locally and verifying the GitHub Actions pipeline.

Flask 3 · pytest Vue 3 · Vite Playwright E2E GitHub Actions

E2E Tests (Playwright)

Playwright starts the Vite dev server automatically. You only need to start the Flask backend manually first.

💡 Backend must be running with seeded data. Run python seed.py once, or set SEED_ON_START=true in .env and restart Flask.
1
Start the backend (separate terminal) 
# From Project-Tracking/backend/
.venv\Scripts\python wsgi.py
# Confirm: * Running on http://127.0.0.1:5000
2
Check backend health 
curl http://localhost:5000/api/health
→ {"db":"postgresql","ok":true}
3
Install Playwright browser (first time only) 
# From Project-Tracking/frontend/
npx playwright install chromium
4
Run all E2E tests 
npx playwright test

# Headed mode (watch the browser):
npx playwright test --headed

# Single spec:
npx playwright test e2e/auth.spec.js
npx playwright test e2e/projects.spec.js
5
View failure report 
npx playwright show-report
# Opens an HTML report with screenshots and traces

CI/CD Pipeline Jobs

Workflow file: .github/workflows/ci.yml. Runs on push and pull_request to main.

Job 1 — backend-test

  • 🐍Python 3.11 on ubuntu-latest
  • 📦Installs requirements-dev.txt (includes dev tools + runtime deps)
  • 🧪Runs python -m pytest tests/ -v --tb=short
  • 🗄️Uses SQLite in-memory via TestConfig — no external DB connection

Job 2 — frontend-build

  • 🟩Node 22 on ubuntu-latest
  • 📦Runs npm ci (clean install from lock file)
  • ⚡Runs npm run build — verifies Vite can compile the full bundle
  • 💾npm cache keyed to frontend/package-lock.json for fast re-runs

Job 3 — e2e (depends on jobs 1 & 2)

  • 🎭Playwright Chromium only in CI (headless, fastest)
  • 🗄️Flask started with DATABASE_URL=sqlite:///ci_e2e.db + SEED_ON_START=true
  • 🌐Frontend served via vite preview --port 5173 (pre-built in same job)
  • 🔁Flaky tests auto-retried up to 2 times in CI
  • 📸Screenshots + videos uploaded as artifact on failure (7-day retention)

Triggering the Pipeline

1
Push to main (automatic) 
git add .
git commit -m "feat: your change"
git push origin main
# Pipeline starts within seconds on GitHub
2
Open a pull request (automatic) 
git checkout -b feature/my-branch
git push origin feature/my-branch
# Open PR on GitHub → pipeline runs against the branch
3
Re-run a failed job manually

GitHub → Actions tab → select the run → Re-run failed jobs button (top right)

Google Sheets Integration

Export all projects to a Google Sheet, or bulk-import new rows from a sheet. Admin users only.

One-time setup

1
Enable the Sheets API

Google Cloud Console → APIs & Services → Library → search Google Sheets API → Enable

2
Create a Service Account and download key

IAM & Admin → Service Accounts → Create → Keys tab → Add Key → JSON → save as backend/credentials.json

3
Share the spreadsheet

Open the Google Sheet → Share → paste the service account email (e.g. app@project-id.iam.gserviceaccount.com) → set role to Editor

4
Add to backend/.env 
GOOGLE_SHEET_ID=your-spreadsheet-id-from-url
GOOGLE_CREDENTIALS_FILE=credentials.json
GOOGLE_SHEET_TAB=Projects          # optional, default: Projects
5
Install packages and restart 
.venv\Scripts\pip install google-api-python-client google-auth
.venv\Scripts\python wsgi.py

Testing the integration

# Replace <token> with a JWT from POST /api/auth/login

# 1. Check configuration (no network call)
curl -H "Authorization: Bearer <token>" http://localhost:5000/api/sheets/status
→ {"configured":true,"sheetId":"...","tab":"Projects"}

# 2. Export all projects to the sheet
curl -X POST -H "Authorization: Bearer <token>" http://localhost:5000/api/sheets/export
→ {"exported":14,"sheetId":"...","tab":"Projects","url":"https://docs.google.com/..."}

# 3. Preview import (dry run — no DB changes)
curl -X POST -H "Authorization: Bearer <token>" "http://localhost:5000/api/sheets/import?preview=1"
→ {"created":3,"skipped":11,"preview":true,"rows":[...]}

# 4. Execute import
curl -X POST -H "Authorization: Bearer <token>" http://localhost:5000/api/sheets/import
→ {"created":3,"skipped":11,"preview":false}
ℹ️ Import rules: Rows whose ID column matches an existing project are skipped — no overwrites. Blank rows and rows with no Name are also skipped. New hand-typed rows (no ID) are always created.

Windows Service (NSSM + ngrok)

The backend can run as a Windows service that starts automatically on boot using waitress as the WSGI server, fronted by an ngrok tunnel for a public HTTPS origin. backend/install_service.bat installs both.

Install (run once as Administrator)

# From Project-Tracking/backend/ — requires NGROK_AUTH_TOKEN + NGROK_DOMAIN in .env
install_service.bat
# Builds the frontend (relative /api base), installs + starts:
#   ProjTracking       — Waitress serving API + built SPA on :5000
#   ProjTrackingNgrok  — ngrok http tunnel → https://<NGROK_DOMAIN>

Manage the services

nssm status  ProjTracking        # SERVICE_RUNNING / STOPPED
nssm status  ProjTrackingNgrok
nssm restart ProjTracking        # after .env changes
nssm restart ProjTrackingNgrok

# Uninstall both (as Administrator):
uninstall_service.bat

Logs

# Written to backend/logs/ — rotates daily at 10 MB
type backend\logs\service.log
type backend\logs\service_error.log
type backend\logs\ngrok.log
type backend\logs\ngrok_error.log
✅ Auto-restart on crash — NSSM restarts both services after a 3-second delay. Logs rotate daily. Backend runs on port 5000 with 4 worker threads; ngrok depends on the backend service being up first.
⚠️ Must run elevated. install_service.bat checks for Administrator rights itself and refuses to continue silently — NSSM otherwise no-ops on install/set/start when not elevated, which can look like success while installing nothing.

Troubleshooting

SymptomRoot causeFix
pytest fails — hydra import error Running global Python Use .venv\Scripts\python -m pytest
Login returns 500 — column users.name does not exist DB_NAME=postgres points to legacy SCADA DB Set DB_NAME=ProjectTracking in backend/.env and restart
CORS error in browser devtools CORS_ORIGINS not set for dev Set CORS_ORIGINS=* in backend/.env
Login 429 Too Many Requests 10 req/min cap hit during testing Wait 60 s or restart Flask
Playwright — Target closed Backend not running when E2E starts Start python wsgi.py before npx playwright test
Playwright — selector not found No seeded data in DB Run .venv\Scripts\python seed.py once
Sheets export returns 503 GOOGLE_* env vars missing Add GOOGLE_SHEET_ID + GOOGLE_CREDENTIALS_FILE to .env
Sheets export returns 502 Service account not shared on spreadsheet Share the sheet with the service account email as Editor
NSSM service won't start waitress not installed in venv .venv\Scripts\pip install waitress
CI e2e job fails — connect ECONNREFUSED :5000 Backend health check loop timed out Check the "Start backend" step logs; usually a missing Python dep in CI
